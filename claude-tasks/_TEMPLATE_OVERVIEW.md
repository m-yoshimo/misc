## 読むもの（実装者・レビュアー共通）

**このタスクを設計・レビューするために事前に読む資料の一覧。** そのファイルだけで辿れる具体度で書く（FLOW-21）。
**`design-review-v2` のレビュアーもこの一覧を読む。** ここに載っていない資料はレビュアーに渡らない。
サブタスク固有の資料は、そのサブタスクの定義書の `## 読むもの` に書く。

| 種別 | 具体度 | 記入 |
|---|---|---|
| **要件（PRD）** | ファイルパス。「PRD を読む」では足りない。**コピーを置くなら `references/prd.md`**（FLOW-05） | |
| **調査記録** | 調査が大きいときは `study.md` に分けてパスを書く | |
| **設計規約** | ファイル単位。ディレクトリ指定なら「配下の全ファイル」と明記 | |
| **参考にする既存コード** | 1ファイルずつのパス。「〜一式」で書かない | |
| **画面デザイン（Figma）** | ファイル URL ＋ ページ名 ＋ section ＋ ノード ID の表、先に読むスキル名、取得できないものとその対処 | |
| **資料の優先順位** | 同じ対象に複数資料があるとき、**どれが正か** | |
| **既知の誤り・制約** | 資料側の誤記、取得できないもの | |

- **該当なしの種別は「不要」と明記する。** 空欄で消さない。
- 画面を伴わないチケットには「Figma の取得は不要」と書く。

## overview と詳細設計の書き分け

| 書く場所 | 書くこと | 書かないこと |
|---|---|---|
| **overview（本書）** | 要件・優先度／基本方針（方向・採らなかった案とその理由・リリースの区切り）／サブタスク一覧（中身・依存）／フィーチャーフラグ一覧／サブタスク間で共有する決め事／複数のサブタスクにまたがる確認事項／決定ログ（方針レベル） | DDL・API スキーマ・関数の形・エラー対応・文言・テストケース・画面の詳細・変更ファイル一覧・ワーカー計画 |
| **詳細設計のファイル** | そのタスクの詳細設計すべて（左の「書かないこと」）／そのタスクだけの確認事項と決定ログ／検証ゲート・コードレビューの表 | overview の決定の書き写し（**節を指すリンクで済ませる**） |
| **study.md**（任意） | 事実・検討した手段・リスク・依頼の原文 | 決定 |
| **release-plan.md** | **全タスク（サブタスク＋サブタスク以外の作業）の順番と進捗**、サブタスク以外の作業の手順 | 決定（overview の決定ログに書く）・詳細設計 |

**更新のルール**

- 詳細設計で、**overview に書いてある項目**（依存・順番・フラグ・共有する決め事・方針）が変わったら、その場で overview を直す。追記ではなく、古い記述を消して書き換える（FLOW-06）
- サブタスクだけに関わる確認事項は、そのサブタスクの定義書を作った時点で overview から移す
