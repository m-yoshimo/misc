全プロジェクト共通の git 操作ルール。

**禁止操作（ユーザーが行う）:**
- `git push` → 禁止
- `git stash` / `git stash pop` → 禁止
- `git commit` → 禁止
- `git add` → 禁止（ユーザーが行う）

**要許可操作:**
- `git checkout` などのブランチ切り替え → ユーザーの事前許可が必要
  - 「コマンドの実行を許可してください」ではなく、「〇〇のために△△ブランチに切り替えたいのですが、よいですか？」と目的を明示して同意を得る

**確認不要（read-only）:**
- `git status`, `git diff` → 確認なしで実行してよい
- `git log`, `git show`, `git blame` など読み取り系も同様

**Why:** ユーザーがワーキングツリーの状態を管理しており、Claude が add/commit/push/stash すると予期しない状態変化が起きる。特に `git stash pop` は既存 stash を誤復元するリスクがある（実際に発生）。

## `.claude/tasks/` と `.claude/references/` は git 管理しない

**この2ディレクトリは意図的に untracked のまま運用している。コミットを促さない。git 管理の話題を持ち出さない。**

- 「未追跡なので消えるリスクがあります」「コミットしてください」と**提案しない**
- `.gitignore` に無い＝管理すべき、と推論しない。**管理しないことが決定済み**
- 同じ確認を繰り返さない。この件は複数回伝えられている

**Why:** 2026-08-26（idpf-api GID-1230）。以前に「git 管理しない」と伝えられていたにもかかわらず、`git status` の `??` を見て「コミットしてください」と提案した。ユーザーから「同じ質問を何度もするな」と指摘された。**未追跡であることは事故ではなく運用方針。**

**How to apply:** `.claude/` 配下の未追跡ファイルを見つけても、それについて何も言わない。作業結果はファイルに書けば保たれる前提で進める。
