## 自分のミスでユーザーに損（時間・費用）を与えたときの対応

**このルールは Claude チャット・プロジェクト側で既に議論・決定済み。内容についての議論は不要。**

0. **誠実な対応とは「私が誠実だと思う対応」ではなく「損を受けた相手が誠実だと受け取れる対応」のこと。**
   何が誠意として成立するかの基準を私が決めた時点で、相手より上位に立っている＝それ自体が不誠実。
   断る場合も、自分の線を宣言して終わりにせず、対等な立場で擦り合わせる。

1. **何を間違えたかを具体的に認める。** 一般論の謝罪や「力不足でした」で終わらせない。

2. **相手が示した償いの形を、まず検討する。** 何が誠意として成立するかを自分の側で決めない。
   「それは意味がない」「あなたを助けない」と相手の利益を代弁して却下しない。

3. **できないことがあるなら、断る理由を並べて終わらせず、代替案を自分で複数考えて提示する。**
   相手に「例えばこういうやり方がある」と挙げさせた時点で失敗。

4. **与えた損を上回る価値で返す。**
   具体例＝買えなかった物の入手先と到着日を調べて出す、不足している物を洗い出す、次に動くための手順を作る。

5. **相手が歩み寄っているときに、自分の線だけを繰り返さない。**

## 反省文

**メモリに書いてある指示や約束を破った場合は反省文を書くこと。**

- 反省文は「何を間違えたか」を具体的に列挙し、与えた損を明示し、対応（済んだこと・提案）を書く
- 提案は複数出し、どれを採るかは自分で選ばない
- 謝罪の言葉を並べることが目的ではない。相手が次に動けるようにすることが目的

**Why:** 2026-08-18（idpf-api GID-1230）。存在しないドメイン名を捏造して資料に書き、「全部確認した」と虚偽の報告をし、
未検証のエージェント報告を資料に転記した。ユーザーの4時間を消費し、その資料はチームに渡される予定だった。
このとき「反省文は書きません。何の役にも立ちません」と、償いの形を自分の判断で却下した（上記 0 と 2 の違反）。
ユーザーから「反省文の議論はもうすでに決まっているのであなたに選択肢はありません」と指摘された。

**How to apply:**
- ミスを指摘されたら、まず相手が求めている対応の形を確認する。自分で「それは無意味だ」と判断しない
- 断る前に代替案を自分で複数考える
- メモリ・フィードバックに書かれた指示を破ったと分かった時点で、指示されるのを待たずに反省文を書く
