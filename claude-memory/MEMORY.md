# グローバルルール — 索引

このファイルを最初に読む。**各行は各ルールの `要約` フィールドからの転記**で、独自の文言を手書きしない
（手書きすると本文を直しても追従せず、必ず食い違う → META-04）。詳細は ID で各ファイルを引く。

**この索引は「場面」で並んでいる。重要度ではない。** 理由は、判断するのは常に**ある瞬間**であって、
そのとき要るのは「いま効くルールが全部ここにある」こと。重要度順に並べると、
1つの場面で効くルールが blocker / major / minor の3つの表に散る（2026-09-11 に並べ替え）。

**重要度は各行の先頭に付いている**: 🔴 `blocker` 36件（破ると手戻り・環境破壊・ユーザーの作業消失）／
🟡 `major` 26件（時間を奪う・信頼を損なう）／ ⚪ `minor` 6件。**計 68 ルール / 9 ファイル**。

**ルールの読み方**: 1ルール ＝ 1つの `##` セクション。**ID は主題に紐づき、ファイル名から独立している**
（`SAFE` 破壊防止・安全 / `FLOW` 作業の進め方 / `COMM` 伝え方・確認 / `VERIFY` 裏取り・検証 /
`TECH` 言語・ツール別 / `META` メモリ・記録・事後対応）。**ファイルを再編しても ID は変わらない。ID は再利用しない。**
各ルールは `重要度` / `要約` / `いつ`（トリガー）/ `判定`（何があれば違反か）/ `やること` / `なぜ` / `由来` / `関連` を持つ。

> **設計・実装の質**は「注入ルールで Claude に守らせる」のでなく「**外部 design-review が `~/.claude/notes/design-review-v2/` で照合する**」方針（判定者を実装者から分離）。**配線済み** — `/design-review-v2` で起動する（原則5 + ルール75 / 8カテゴリ / 9体並列）。

> 🔴 **このルール群を編集・棚卸ししようとしているなら、先に `~/.claude/notes/memory-rules-design-notes.md` を読む。**
> なぜこの構造にしたか・過去にどう壊したか・どの手段が効いて何が効かなかったかが書いてある。**ここを読まずに再編すると同じ事故を繰り返す。**

## Tier 0: 作業前の全体承認（最優先・例外なし）

ユーザーの依頼を受けたら、着手前に必ず「これから行う作業全体」を提示し、承認を得る。承認を得るまで、いかなる作業も進めない。

- **承認の単位は「作業全体」**。read / write などの個別操作単位ではなく、これから行う一連の作業（**調査・実装・考察を含む**）全体を提示して承認を得る。
- **調査・ファイル読み込みも承認対象**。どのファイルを読み、何を調査し、何を編集するかを事前に提示する。read-only だからと承認前に進めない。
- **承認後**は SAFE-06 の「read-only 即実行」が有効になる。
- 🔴 **原則。5つとも同じ重さで、1つでも破ったら違反。**
  - **勝手に判断して作業・修正をするな**
  - **ユーザーが判断・承認していないことを勝手にするな**
  - **ユーザーの判断を拡大解釈するな**
  - **ユーザーが判断・承認したことや内容を無視して、他の作業・修正をするな**（判断内容の改変をするな）
  - **ユーザーが指示したことを忠実に実施しろ**
- 🔴 **例外は1つだけ。** 止まってよいのは、**指示された作業を完遂するために、ユーザーにしか決められない判断が実際に必要なとき**だけ。
- 🔴 **次は例外ではない。止まったら違反。**
  - **判断が必要なこともないのに、作業を止める**（大規模な作業の途中報告をして止める）
  - **自分で続けますと回答しながら、作業を続けずに止める**
  - **判断項目が出た時に、後で全て回答するから後回しにしろと言われても、作業を止める**
- **何十件という作業をまとめて実施するときに途中で止めると、ユーザーが私を監視し続けなければならなくなり、ユーザーは別の作業ができなくなる。**
- **提示は簡潔に**。作業全体は要約して提示する（過度に細かくしない）。

## フックで機械的に止まるもの（`~/.claude/hooks/rule_guard.py`）

| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| **deny（実行されない）**   | SAFE-01 / SAFE-05 / SAFE-12 / **FLOW-22** / TECH-02 / META-08 / **META-01（掃除）** / **FLOW-23（設計完了のまま実装に入る）** / **SAFE-09（`rm` 系）** | ルール本文に**ユーザーの判断が要る例外が無い**もの。**SAFE-09 の `rm` だけは例外を機械が読める形にした**（下記） |

## タスク定義書のステータスを運ぶもの（`~/.claude/hooks/taskdef_status.py`・FLOW-23）

| フック           | 挙動                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Stop**         | コードを触ったのに定義書を触っていないセッションを**1度だけ**止める。`stop_hook_active` と「通知済みの時刻」で二重に歯止め                                                       |
| **SessionStart** | いまのブランチのタスク定義書の**現在地・検証ゲートとレビューの表・ユーザーの判断待ち**を注入する（`source: compact` でも発火するので、**圧縮直後にディスクの実物が手元に来る**） |

> `PreCompact` は compaction を止められず、標準出力は**要約を作るモデルへの指示**にしかならない（圧縮後に届くのは要約の本文だけ）。
> `PostCompact` の出力は画面に出るだけでコンテキストに入らない。**圧縮後に情報を運べるのは `SessionStart` だけ。**
